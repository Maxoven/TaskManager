# Task Manager — backend

Node.js (Express) + PostgreSQL. Отдаёт API на `/api`, шлёт письма через SMTP и по расписанию напоминает о дедлайнах.

## Установка

```bash
cd backend
npm install
cp .env.example .env   # заполнить DB_*, JWT_SECRET, SMTP_*, FRONTEND_URL
npm run db:init        # создаёт/обновляет таблицы (скрипт идемпотентный)
npm start
```

В консоли должно появиться `🚀 Сервер запущен на порту 3001`. Проверка: `GET /api` → `{"message":"Task Manager API работает!"}`.

Без `JWT_SECRET` сервер не стартует — задайте длинную случайную строку (32+ символа).

После обновления кода достаточно повторить `npm install` и `npm run db:init` — существующие данные скрипт не трогает.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` или `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_SSL` | Подключение к PostgreSQL |
| `JWT_SECRET` | Секрет подписи токенов (обязателен) |
| `PORT` | Порт API, по умолчанию 3001 |
| `FRONTEND_URL` | Адрес сайта — подставляется в ссылки из писем |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | Почта |
| `UPLOADS_DIR` | Папка файлов задач, по умолчанию `backend/storage/uploads` |
| `AVATARS_DIR` | Папка фото профиля, по умолчанию `backend/storage/avatars` |
| `DEEPSEEK_API_KEY` | Ключ DeepSeek для ИИ-ассистента. Без него ассистент не показывается |
| `MCP_PUBLIC_URL` | Необязательно: публичный адрес сайта для MCP и OAuth. По умолчанию `FRONTEND_URL` |
| `REGISTRATION_OPEN_DOMAINS` | Необязательно: домены почты, с которыми регистрация сразу. По умолчанию `ecosana.club,ecoestate.tv` |
| `REGISTRATION_APPROVER_EMAIL` | Необязательно: кому приходят заявки на регистрацию с других адресов. По умолчанию `maksim.vakulenko@ecosana.club` |
| `DEEPSEEK_MODEL` | Необязательно: конкретная модель. По умолчанию выбирается быстрая «flash» из доступных ключу |

## Структура

```
backend/
├── server.js             # точка входа
├── config/database.js    # пул PostgreSQL, withTransaction
├── middleware/           # auth (JWT), lang (язык ответа), rateLimit
├── routes/               # auth, avatars, projects, tasks, reports (magic link), teams, inbox (входящие, голос), assistant (ИИ)
├── mcp/                  # MCP-сервер для ИИ-клиентов: index (/api/mcp), oauth (вход), tools (инструменты)
├── services/             # access (права), email, scheduler (напоминания), ai (DeepSeek), fileReader (чтение файлов для ИИ)
├── i18n/messages.js      # тексты ответов API (ru/en)
├── scripts/              # init-db, migrate-from-mysql
└── database-init.sql     # схема
```

## Регистрация по заявке

С почтой из `REGISTRATION_OPEN_DOMAINS` (по умолчанию `ecosana.club`, `ecoestate.tv`) регистрируются как обычно: письмо → подтверждение → вход. С любой другой почтой аккаунт сразу не создаётся: форма сохраняет заявку (`registration_requests`, пароль — bcrypt-хешем) и шлёт письмо на `REGISTRATION_APPROVER_EMAIL`. В письме — ссылка на страницу заявки `/registration-requests/:token` с кнопками «Разрешить» и «Отклонить»; ссылка одноразового решения работает без входа, в базе хранится только SHA-256 токена, а решение принимается только нажатием (POST), поэтому почтовые сканеры ничего не одобрят. После «Разрешить» создаётся пользователь, и заявителю приходит письмо со ссылкой (7 дней), которая подтверждает почту и входит. После «Отклонить» — письмо об отказе. Пока заявка не рассмотрена, при входе с паролем из заявки человеку пишут, что она на рассмотрении. Повторная заявка с той же почтой обновляет прежнюю; одобряющему пишем не чаще раза в час.

## Команды и роли

Пользователь может состоять в нескольких командах и переключаться между ними. Проект принадлежит команде (`projects.team_id`), доступ даёт членство в ней (`team_memberships`) и настройка проекта `projects.visibility`:

- `team` — проект видит вся команда, включая тех, кто вступит позже;
- `selected` — только отмеченные люди (`project_access`). Так по умолчанию создаются новые проекты.

| Роль | Что может |
|---|---|
| `owner` | создатель команды: видит все её проекты, приглашает людей, меняет роли, удаляет команду |
| `admin` | создаёт проекты и ведёт доступные ему: меняет, удаляет, решает, кто их видит |
| `member` | работает с задачами в доступных ему проектах |

Отдельно можно пригласить человека только в один проект (`project_members`) — это гость с правами участника в этом проекте. Все проверки прав — в `services/access.js`.

При первом `npm run db:init` после обновления старая модель «одна команда на владельца» (`team_members`) переносится автоматически: у каждого владельца проектов появляется своя команда, прежние участники становятся `member`, а их проекты получают `visibility = 'team'` (доступ не меняется); старая таблица переименовывается в `team_members_legacy`.

## Срок и файлы проекта

У проекта могут быть дата начала и ожидаемая дата завершения (`projects.start_date`, `projects.due_date`; завершение не раньше начала): видны на карточке, на доске и пунктирами на графике. К проекту, как и к задаче, можно прикреплять файлы (`project_attachments`, `/api/projects/:id/attachments`) — те же форматы и лимит 10 МБ, файлы лежат в `UPLOADS_DIR`. Добавлять может любой участник проекта, удалять — тот, кто загрузил, или владелец/админ. ИИ-ассистент и MCP видят срок и файлы проекта.

На главной по умолчанию показываются только проекты с задачами; пустые открываются кнопкой «Показать пустые проекты» (выбор запоминается в браузере).

## Входящие и голосовой ввод

Как Inbox, Quick Add и Ramble в Todoist. «Входящие» (`inbox_items`) — личный список задач пользователя, записанных на ходу; другим не виден. Из любого места: `Q` — быстро добавить (строка вида «Позвонить завтра #Офис» сама распознаёт срок и проект), `Shift+Q` — надиктовать. Разбирая входящие, запись переносят в проект (`POST /api/inbox/move`) — она становится обычной задачей в выбранной колонке с исполнителями.

Речь в текст переводит браузер (Web Speech API: Chrome, Edge, Safari; в Firefox — ввод текстом), а текст на задачи разбирает DeepSeek (`POST /api/inbox/voice/parse`), поэтому голосовой ввод работает только при заданном `DEEPSEEK_API_KEY`. Звук на сервер не передаётся и не хранится.

## MCP-сервер для ИИ

По адресу `https://<сайт>/api/mcp` работает MCP-сервер (Model Context Protocol, Streamable HTTP). Через него ИИ-клиент — Claude (claude.ai, Claude Desktop, Claude Code), Claude Managed Agents или любой другой клиент MCP — управляет Task Manager от имени пользователя: команды, проекты, доступ, задачи, исполнители, сроки, «Входящие», загрузка.

**Вход — логин и пароль аккаунта**, по OAuth 2.1: клиент сам регистрируется, открывает страницу входа `/api/mcp/oauth/authorize`, человек вводит email и пароль, клиент получает токены. Пароль ИИ не видит. Access-токен живёт час, refresh-токен — 60 дней и меняется при каждом обновлении. Коды и refresh-токены хранятся только как SHA-256 (`mcp_oauth_*`). Токены MCP не подходят к обычному API, и наоборот.

**Права — ровно как у пользователя.** Каждый инструмент вызывает тот же REST API, что и сайт, от его имени, поэтому действуют все проверки из `services/access.js`. Удаление помечено для клиента как необратимое (`destructiveHint`).

Подключить в Claude: Настройки → Коннекторы → «Добавить свой коннектор» → адрес `https://taskmanager.ecoestate.tv/api/mcp` → «Подключить» → войти. В Claude Code: `claude mcp add --transport http taskmanager https://taskmanager.ecoestate.tv/api/mcp`, затем `/mcp` → войти.

**Nginx:** клиенты ищут метаданные OAuth в корне сайта, поэтому кроме `/api` на API нужно проксировать `/.well-known/oauth-`:

```nginx
location /.well-known/oauth- {
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

Проверка: `curl https://<сайт>/.well-known/oauth-authorization-server` возвращает JSON, а `curl -i -X POST https://<сайт>/api/mcp` — `401` с заголовком `WWW-Authenticate`.

Отозвать доступ: сменить пароль через «Забыли пароль?» — это гасит все refresh-токены пользователя (или вручную: `UPDATE mcp_oauth_refresh_tokens SET revoked_at = NOW() WHERE user_id = …`). Уже выданный access-токен перестаёт работать не позже чем через час.

### Почта в MCP

Если корпоративная почта пользователя на one.com (MX домена — `*.one.com`, сейчас это `ecoestate.tv` и `ecosana.club`) и пароль от неё совпадает с паролем таскменеджера, при входе в коннектор сервер проверяет пароль на `imap.one.com` и подключает ящик. Тогда в том же коннекторе появляются инструменты `mail_*`: папки, поиск, чтение писем и вложений, флажки, перенос, удаление в корзину, отправка, ответ, пересылка, черновики, сохранение вложения в задачу и файлы задач во вложения письма. Отправленное кладётся в «Отправленные».

У one.com нет OAuth, поэтому пароль от почты хранится в `mail_accounts` зашифрованным (AES-256-GCM, ключ `MAIL_ENCRYPTION_KEY` в `.env`, в базе его нет). Пароли других почтовых сервисов никуда не отправляются. Сброс пароля таскменеджера удаляет сохранённый пароль почты; если пароль от почты сменили, инструменты сообщают, что нужно войти в коннектор заново.

## Развёртывание

- API работает за nginx: `/api` проксируется на `PORT`. Nginx должен передавать `X-Forwarded-For` — по нему считается лимит попыток входа.
- Файлы задач лежат вне раздаваемой nginx папки и скачиваются только через API с проверкой доступа. Папки `UPLOADS_DIR` и `AVATARS_DIR` нужно включить в резервные копии.
- Напоминания рассылаются в 9:00, 10:00 и 11:00 по времени сервера — процесс должен работать постоянно (pm2, systemd или менеджер Node.js-приложений хостинга).
- Перенос данных из старой MySQL-базы: `npm run db:migrate-mysql` (см. комментарии в `scripts/migrate-from-mysql.js`).
